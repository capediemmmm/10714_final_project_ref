在 Needle 中支持稀疏矩阵与图神经网络
两人项目计划，供 2026 年 11 月 10 日与导师讨论

项目范围

我们计划在 Needle 中添加一个 CPU 算子，用于计算二维稀疏矩阵与稠密特征矩阵的乘积。该算子支持对稀疏矩阵中存储的数值和稠密输入分别求一阶梯度。我们会用它在 Cora 数据集上训练一个两层图卷积网络（GCN），并与使用 Needle 稠密运算的同一模型进行比较。

希望与导师讨论三个问题。
1. 对两人小组而言，在 CPU 上实现该算子、两类输入的梯度以及可端到端训练的 GCN，项目范围是否合适？
2. Cora 的图结构是固定的。能否在算子测试中展示对稀疏矩阵存储值的求导能力，而在 GCN 实验中只更新模型权重并测量训练开销？
3. 以稠密实现为参照的正确性测试，加上条件一致的 Cora 对照实验，是否足以支撑项目结论？如果时间允许，改变图密度做一组小实验和增加训练重复次数，哪一项更有价值？

两人分工

成员 A 负责稀疏矩阵的存储、计算和内存测量。A 将实现压缩稀疏行（CSR）格式的构造、CPU 前向和反向计算内核，以及它们与 Needle 的接口。A 将记录实现中分配了哪些数组，测量邻接矩阵的存储大小和进程峰值内存，并撰写报告中的系统设计和内存分析部分。

成员 B 负责独立的参考实现、数据、模型和训练实验。B 将编写以稠密计算为参照的测试，加载 Cora 数据及其公开划分，实现 GCN 和使用掩码的损失函数，并用同一份训练脚本运行两个版本。B 将记录训练耗时和准确率，撰写模型与实验评估部分。

动手编码前，两人先约定接口。A 开发稀疏算子期间，B 可以用稠密矩阵乘法搭建模型。集成时，B 用独立编写的测试检查 A 的算子，A 则检查 B 的两种模型是否使用相同的图、权重和损失函数。两人分别在全新的 Colab 会话中运行对方的一部分工作。

第一阶段的编码任务

从 hw4_extra/assignment 建立项目的私有副本。A 从 src/ndarray_backend_cpu.cc 入手，参考 python/needle/ops/ops_mathematic.py 中的 MatMul 类，了解如何编写 Needle TensorOp。B 先编写一个小型算子测试，并在 apps/ 中实现使用稠密计算的图卷积层。两人都显式选择 ndl.cpu()，确保两个版本均运行在 Needle 原生 CPU 后端上。

约定接口 Y = spmm(A, X)。如果 A 的形状是 (m, n)，X 的形状是 (n, f)，则 Y 的形状是 (m, f)。稀疏矩阵 A 使用固定的整数数组存储行偏移和列索引，用一个 float32 类型的 Needle 张量存储数值。数值张量 values 和特征张量 X 是算子的两个张量输入，反向传播可分别返回它们的梯度。行偏移和列索引作为元数据保存在算子中。构造矩阵时检查维度和索引范围。从带权边列表构造 CSR 时，将相同坐标的权重相加。

用下面的手算例子做第一个验收测试。
  A = [[0, 2, 0], [3, 0, 4]]
  row_offsets = [0, 1, 3], col_indices = [1, 0, 2], values = [2, 3, 4]
  X = [[1], [2], [-1]]
  预期输出 Y = [[4], [-1]]
  若 loss = Y[0,0] + 2 * Y[1,0]，则预期 X.grad = [[6], [2], [8]]，
  按 CSR 存储顺序，预期 values.grad = [2, 2, -2]。

A 编写的前向内核遍历每个已存储的元素 (i, j)，将该元素的值乘以 X[j, :]，再累加到输出的第 i 行。设输出端传回的梯度为 G，则稠密输入的梯度为 A.T @ G。坐标 (i, j) 处存储值的梯度为 dot(G[i, :], X[j, :])。这两项反向计算都只需遍历已存储的元素，并将贡献直接累加到各自的输出缓冲区。

B 用 Needle 的稠密计算结果核对前向输出、X 的梯度和存储值的梯度。测试覆盖非方阵、空行、重复输入坐标和多列特征。反向测试使用各位置取值不同的输出梯度，便于发现转置或行索引错误。另选一个小样例，每次只扰动一个输入数值，测量标量损失的变化，用有限差分抽查两类解析梯度中的若干元素。

GCN 与实验设计

B 加载 Cora 的公开数据划分，确认节点特征、标签和掩码中的节点顺序一致。构造无向的 0/1 邻接矩阵，合并重复边，为每个节点添加一条自环，然后按节点度数做一次对称归一化。从同一组归一化后的元素构造稀疏和稠密两种表示，节点特征均使用稠密矩阵。对于权重为 W 的图卷积层，先计算 X @ W，再用归一化邻接矩阵左乘该结果。在两层之间使用 ReLU。用 Needle 算子计算每个节点的交叉熵，乘以训练掩码后求和，再除以训练节点数。

验证正确性时，两个模型使用相同的初始权重，并关闭 dropout。比较两者的 logits（分类得分）、应用掩码后的损失、两层权重各自的梯度，以及优化器更新一次后的权重。对小样例的 float32 解析结果，先用 rtol=1e-4 和 atol=1e-5 作为相对和绝对误差容限。记录最大误差，排查超出容限的差异。

比较训练开销时，归一化邻接矩阵是固定的。HW4 Extra 的自动微分循环会将梯度传给算子的每个张量输入。因此，A 和 B 分别为稀疏和稠密实现提供固定邻接矩阵的算子，把特征矩阵作为唯一的张量输入，并在反向传播时返回其梯度。这样可以测量两个模型在固定图上训练所需的工作。A 的通用 spmm 仍支持对可训练的存储值求导，这项功能将单独测试。

两个版本使用相同类型的 CPU 运行环境、数据划分、初始权重、优化器和训练轮数。先做一次短时间试跑，据此选定两个模型都能承担的训练轮数。根据验证集准确率选择设置，再报告所选设置的测试集准确率。计时排除数据加载和编译，两个版本都先预热，再记录每轮训练耗时的中位数。内存方面，按字节统计 CSR 数值、列索引和行偏移的总大小，与稠密邻接矩阵的字节数比较。每种表示各在独立的新进程中加载，分别测量进程峰值内存。将实验设置、随机种子和原始测量数据与结果一同保存。
